## Demo 邊界

- 本作品是黑客松 demo，以主辦方提供的固定歷史 Excel 遙測資料進行分析；不串接真實即時車機、駕駛、訂單、人資或保修系統。
- 地圖、車況、油耗與 DTC 顯示的是來源資料的歷史紀錄或最後快照，不是即時位置、即時告警或即時任務。
- 疲勞、繞行、超載、點檢、推播、調度與保修預約皆在「情境模擬實驗室」中以明確標示的虛構事件展示；不會真的發送通知、派工、停派或預約，也不會寫回原始資料。
- 角色切換與回報／送出按鈕只用於介面展示，並非正式帳號、權限或工作流系統。

## 五角色系統
- **車隊管理（RWD 會議台）**：以歷史遙測資料示範車隊覆核、車號比較、安全指標與情境模擬。
- **總負責人（RWD 管理台）**：以區域／車號歷史資料示範 KPI 判讀與改善清單。
- **車輛使用者（App）**：查看車號的歷史訊號摘要與資料限制；不宣稱即時提醒或個人績效。
- **個人用戶（App）**：展示最小化的車號歷史快照。
- **貨主（App）**：展示資料不足時的隱私保護與 ETA 限制，不提供真實貨況服務。

## iTRAQ WEB 與 RWD

- 車隊管理與總負責人使用 iTRAQ 風格的資料快照、歷史車輛、任務／保修介面與數據中心；未由來源提供的流程只作清楚標示的情境展示，不以手冊或簡報截圖當作頁面內容。
- 全站遙測數據由 `output data_Hotai_20260511.xlsx` 編譯為 `excel-derived-data.js`：車號、時間、車輛狀態、GPS、車速／限速、怠速、高引擎負載、油耗、里程、DTC 與 journeyCode 都可追溯到原始欄位。更新來源活頁簿後，執行 `python3 scripts/build_excel_demo_data_stream.py` 重新產生前端資料。
- 已確認 Excel 有 event[0..2].type、起訖時間與 duration 等事件欄位。事件代碼的語意仍需對照官方字典，不能把車機訊號當作確認的人員狀態。來源沒有駕駛姓名、手機、工時、出勤、薪酬、職級、訂單、ETA 與準時率，不能據此做人事決策。
- 地圖顯示各車最後 GPS 紀錄；DVR 為模擬畫面。任務、保修、通知與事件處置僅展示使用者流程與資料缺口，並不代表後端已執行。
- 所有角色在手機、平板與桌機寬度皆採同一套自適應版型；桌機會展開成寬版工作台，手機維持易操作的 App 介面。

## 安全聯賽與人資原則

- 團隊排名可公開比較；駕駛只能看到自己的名次，不能看到其他同仁姓名或名次。
- 獎勵以安全改善與達標為主，禁止用多接單、縮短休息或違規趕工換分數。
- 安全分不會自動扣薪、解雇或觸發裁員；低分先進入 30 天改善、申訴與人資／主管覆核。
- 車隊管理端僅以 journeyCode 與車號數提供車輛量能覆核；招募、薪酬與裁員會要求先串接人資與訂單資料，且所有人事決定均需人工核准。

> 所有非歷史 Excel 欄位的事件與處置，均使用明確標示的情境模擬；歷史遙測資料可追溯至來源欄位。


## 智慧夥伴工作台（2026-09 優化）

管理者與駕駛的新主入口提供省油／安全證據卡、承接角色與日期、覆核與回報歷程、本機保存及 JSON 匯出。狀態到「待量測」為止，不會自動認定已有改善。

效益頁以同月合格車群總油量／總里程建立加權基線，提供明示假設的節省試算、人工前後觀測與六週對照試點設計。資料頁揭露缺測月份、示範區域與尚未完成的安全預測能力。

完整題目對照、重大缺口、量測方法及展示順序見 [題目對照與優化評估](docs/題目對照與優化評估.md)。本次重新讀取 Excel 欄位並編譯缺測資料。缺測月份改為 null，圖表保留缺口；新工作台不使用未核對事件語意作結論。

驗證：`node --test tests/partner.test.js`、`npm run build`。

本機完整服務：`npm start`（預設 8080）。配置伺服器環境變數 `GEMINI_API_KEY` 或 `GOOGLE_API_KEY` 後，管理者對話才會呼叫 Gemini；未配置時顯示規則摘要。純 Vite dev 或靜態託管沒有 `/api/chat` 後端時同樣使用規則模式。不得把 API key 放進前端。
